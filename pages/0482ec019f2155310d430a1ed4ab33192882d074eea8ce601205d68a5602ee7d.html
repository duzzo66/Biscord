Discord Patch Notes: September 8, 2026

Discord Engineering
September 8, 2026

Welcome to Patch Notes! In this series, we comb through the newest changes in performance, reliability, responsiveness, usability, and general bug-squishing we’ve done to make Discord better. 

If you discover an issue of your own, check out our Bimonthly Bug Megathread on the community-run r/DiscordApp subreddit. Tell us what’s been bothering you, and our Engineering team will be more than happy to check it out. 

All fixes listed below have been committed and merged, but may still be rolling out to individual platforms at the time of this post. 

Highlights

  • We recently shipped system wide echo cancellation on Windows clients. Historically, echo cancellation was focused on just audio from Discord calls; nothing else happening on your PC was accounted for. Now, we attempt to remove a much broader set of things, which should result in your friends complaining less about being able to hear the TV show re-runs you're watching on your second monitor. We understand the glory of multi-tasking, we just don't want to hear it in calls with you anymore ♥️. 
  • We recently upgraded React Native from .81 to .86 in our mobile apps. This came with a handful of incremental performance gains, and some minor regressions that have been solved since. Net effect is average CPU usage across Android and iOS improved by ~5%, and average app launch times improved about the same amount. 
  • We also upgraded our Electron version to 42 for the Desktop app and changed some of the ways we consume it. These changes yielded some very nice p50 CPU usage improvements (~17%) at the cost of a smaller regression to p50 memory usage (~4%). The fewer resources we use, the more you have for gaming… and we know where your priority is.
  • On Desktop, we recently shipped another change that improved p50 CPU usage by ~3%. This change contained a couple of optimizations that reduce the number of unnecessary elements we attempt to render. Sometimes code clean-up can have really nice side-effects like this.
  • We upgraded the free upload limit from 10MB to 20MB across all platforms. More details can be found in the announcement here.

  • Fixed a bug on Desktop where tabbing through Mod View would land keyboard focus on disabled actions (like DM, Kick, Ban, or Timeout on yourself); screen readers now correctly announce them as unavailable and focus skips over them.
  • Screen readers on Android now announce the names of the color options when customizing display name styles, instead of just their roles.
  • Fixed a bug on Desktop where keyboard focus rings in the Active Now sidebar appeared misaligned with the elements they were highlighting.
  • Fixed an issue on iOS and Android where screen readers didn't announce the number of Boosts on the Boost goal button. Screen readers now read out the full progress (like "0/33 Boosts").
  • Screen readers on iOS and Android now correctly announce the 'Nitro Plans', 'Nitro + Boost Plans', and 'Boost Plans' section titles as headings on the Choose a Plan screen when boosting a server.
  • Screen readers now correctly announce the section titles on the Server Boost page (like "Top perks you can unlock" and "Boosting FAQ") as headings on iOS and Android.
  • Screen readers on Desktop now announce when you've reached the character limit while setting your custom status.
  • Fixed a bug on Desktop where keyboard focus wasn't trapped in the emoji picker while editing your profile bio, so tabbing past the last element would close the picker and exit editing. Focus now loops within the picker until you close it.
  • Fixed an issue on iOS and Android where screen reader users couldn't activate the "Send" button in the app launcher's recent commands list. Send is now available as a custom accessibility action on each command row.
  • Resolved a bug on Desktop where shift+tabbing backward through the forum composer could trap keyboard focus on nothing, leaving further tab presses with no effect.
  • Screen readers on iOS and Android now announce when a message was sent silently.
  • Resolved an issue on Desktop where pressing ESC wouldn't close the emoji picker if a category (like Favorites or Frequently Used) had keyboard focus.
  • Fixed an issue on Android where, after completing a Nitro purchase, screen readers would land on the Dismiss button instead of the confirmation. Focus now moves to the top of the confirmation, and the activation banner is properly announced.
  • Fixed a bug on Desktop where server invite previews with nothing to expand still created a dead keyboard focus stop; they're now grouped and labeled properly for keyboard and screen reader users, with Join or Go to Server as the direct action.
  • Screen readers now announce custom statuses with proper context (like "Pickle's custom status") instead of just reading the status text on its own.
  • Fixed an issue on Desktop where a custom status could be focused like a button but didn't do anything when activated. Keyboard users now get a proper expand/collapse button, and screen readers announce the status with the correct role.
  • Fixed an issue on Desktop where screen readers would announce the custom status preview description even when no preview was showing.
  • Fixed a bug on Desktop where using keyboard navigation to trigger Shift-click shortcuts (like removing a profile widget without the confirmation modal) still showed the modal — the very one telling you to hold Shift to skip it.
  • Fixed an issue on Desktop where adding or clearing your custom status via keyboard would send focus back to the start of the profile modal instead of the element you were on.

All relative measurements cited were performed internally with our own instrumentation and tooling.
